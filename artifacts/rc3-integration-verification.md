### 启动命令与一个 CLI 用法要点

计划中的 `dsh --profile retitle-spike --patch ... web --port 0 --no-open` 会失败：

```text
error: too many arguments. Expected 0 arguments but got 1: web.
```

原因：该 profile 组成已自动选中 web app，`web` 只能作为“选择 profile”的位置参数（`dsh web`），不能再作为 app 参数传入。正确启动命令：

```bash
DSH_HOME=/tmp/dsh-rc3-verify \
  '/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh' \
  --profile retitle-spike --patch /tmp/rc3-verify-patch.yml --port 0 --no-open
```

服务输出（token 脱敏）：

```text
dsh web: http://127.0.0.1:65462/?token=<REDACTED>
```

仅监听 `127.0.0.1`，未绑定 0.0.0.0；验证结束后已 kill 后台任务，`lsof` 确认 65462 端口释放，桌面实例 61361 未受影响。

## 7. 用户需要执行的操作（重要）

Desktop 的 `retitle-spike`/desktop profile 采用 `link:` 安装，**Host 与 Client bundle 只在 DSH 启动时组合一次**：

- 插件页“刷新”不会重新加载宿主配置；
- 当前运行中的 Desktop 进程仍加载旧构建（0.1.0 或 rc.2 之前的组合代）；
- **用户需要完全退出并重新打开 Desktop DSH**，才会加载 0.1.1 的 Host+Client 构建；重启会结束当前会话。
